## 2. 数据库究竟怎么存，CREATE 写到哪里

本项目是自己实现的教学数据库内核，有查询编译、执行器、索引、缓冲区、磁盘页和事务恢复；没有把 SQL 交给 SQLite 或其他现成数据库执行。当前 SQL 是明确支持的子集，不代表完整 SQL 标准。

正式工作台使用 A 模块的分页存储：每个**逻辑页为 4096 字节**，页头包含类型标记、页号、事务日志位置和校验信息，页内结构以 JSON 编码。新版工作台把整个页加密之后再写磁盘，所以磁盘上的页文件比 4096 字节略大，不能再直接当 JSON 阅读。使用 JSON 作为内部编码不等于把数据库实现成普通文本文件。

默认目录结构如下；启动时指定 `--db 路径`，则以该路径替换根目录。

```text
.edudb_workbench_v2/
  security/
    key.dpapi                 Windows 当前账号保护的数据密钥
    users.vault               加密的账号、角色、授权和密码校验资料
    audit.vault               加密审计记录
  database/
    protected.json            受保护格式标记，不包含解密密钥
    a_storage/
      storage.json            存储格式标记
      pages/<对象编号的散列>/0000000000.page
    wal/contract.wal          加密的事务日志
    contract_runtime.lock     防止多个进程同时打开同一数据库
```

- `CREATE TABLE` 把表名、列、类型、约束和持久对象编号登记到目录页，并写入事务日志。刚建空表时不必立即分配记录页，首次插入才分配；不会在桌面出现一个叫 `students.json` 的文件。
- `INSERT` 把记录写到该表的数据页，更新页先进入缓冲区，再按日志先落盘的规则写回硬盘；提交和恢复共同保证持久性。
- `CREATE INDEX` 创建独立对象编号和索引页，保存树节点及指向记录的位置。
- `CREATE VIEW` 保存查询定义、输出列和依赖关系；查询时展开执行，不复制一份查询结果。
- 表、索引和目录通过对象编号寻址，文件夹名经过散列。**散列文件名本身不提供内容保密，真正保护内容的是页加密。**
- 项目目前没有 `CREATE DATABASE` 语句。选择或新建一个数据库，是启动程序时指定 `--db` 数据目录。

## 3. 先预估，再做优化实验

优化实验室新增“预估开销”。该按钮只编译、检查权限并收集统计信息，不执行目标查询；“运行对比”会先展示预估，再运行两种计划。网页和导出的报告都包含预估与实测。

| 项目 | 显示内容 |
|---|---|
| 时间复杂度 | 扫描约为 O(n)，索引定位约为 O(log₈ n+k)，排序约为 O(n log n)，嵌套循环连接约为 O(n×m+k)，哈希连接平均约为 O(n+m+k) |
| 行级计算量 | 每个算子的输入行数、输出列数或连接组合数形成的模型单位 |
| 数据和索引访问 | 数据页、索引页、合计访问页数的分别估算 |
| 内存 | 模型预计保留的行数，不冒充准确字节数或严格上界 |
| 实际实验 | 规划耗时、执行耗时、数据页读取、索引页读取、总读页、多次中位数、结果一致性 |

n、m 表示相关输入规模，k 表示匹配或输出规模；不同算子的输入规模可能不同。复杂度描述随规模增长的趋势，不能直接换成多少毫秒。

模型使用真实表行数和页数，但尚无数据分布直方图；普通筛选、范围筛选和非唯一等值使用明确公开的比例假设。统计信息收集本身会读页，随后实验重置应用缓冲区，避免把统计收集当成查询结果或查询计时。操作系统缓存仍然存在。

例如默认 20 人、按唯一编号查一人时，模型可显示关闭优化计算量约 42、开启约 5；但全表本身可能只有一个数据页，走索引会多读索引页。因此不保证“开启优化一定更快”。当前优化器仍主要按规则改写，新增的是效果预估与对比功能，没有宣称已经实现完善的按成本选计划。

相关子查询、数据倾斜、缓存、真实树形状和加密开销可能造成估计偏差；实测结果始终独立展示，不反过来伪造预估。

## 4. 用户创建与存取

登录页可以创建普通账号。管理员仍可在“用户与权限”创建账号并设置角色及授权。

1. 用户名为 3～32 位小写字母、数字或下划线，以字母开头；密码 12～128 个字符。
2. 自助注册只能创建普通成员，不能提交管理员角色或自选权限；新账号默认没有任何表权限。
3. 管理员选择成员、数据表或视图，授予读取、插入、更新、删除权限。视图本轮只支持读取，写入视图会被执行层拒绝。
4. 密码不保存原文，也不采用可解密方式保存；每个用户使用独立随机盐和 60 万次密码摘要计算，登录时重新计算并比较。
5. 用户名、角色、授权、盐和密码摘要作为整体，经过带认证加密后存入 `users.vault`。修改角色字节或把文件搬到其他上下文会导致校验失败。
6. 文件损坏、密钥缺失或身份文件被删除时，程序拒绝打开，不自动重置成管理员或免登录状态。授权和账号重启后仍保存。

账号文件内部仍需要结构化编码；安全性来自口令摘要、身份文件加密与完整性验证、密钥保管和权限检查，而不是单纯把 JSON 改成其他扩展名。

## 5. 本地文件绕过登录：已做与边界

新版工作台不只加密账号，还加密**数据页、目录内容、事务日志与审计记录**。使用随机 256 位数据密钥，每次加密生成新的随机数，并验证密文与文件上下文。密钥再交给 Windows 当前账号保护，没有写死在代码里。无密钥的开发运行时也会拒绝打开受保护目录。

这解决了直接拿到新版页文件后用文本工具查看数据，以及直接改普通账号文件成为管理员的问题。加密文件被改动时会报错；它不保证阻止删除文件、回退整个历史快照，也不加密运行中内存、截图或用户主动导出的查询结果。

**同一个 Windows 账号下能运行程序的人，仍可能调用系统解锁密钥。应用登录不能隔离这个操作系统账号的拥有者。** 若要求多个不互相信任的人共用设备且各自只能经登录访问，应把数据库进程和数据目录放到独立服务账号，普通用户只有客户端访问权限；更强隔离可使用独立服务器。此类服务部署本轮未实施，不能把加密或打包成可执行程序当作这种隔离。

Windows 账号保护通常要求相同登录凭据及原机器；漫游配置等情形有例外。请保留完整备份与原 Windows 账号环境，不要把“复制目录到另一台电脑”当作可靠迁移方式。[微软保护机制说明](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。密文认证与上下文验证使用标准加密库提供的能力。[加密库说明](https://cryptography.io/en/latest/hazmat/primitives/aead/)。
