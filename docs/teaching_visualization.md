## 二、新增的三个可视化

| 功能 | 操作和效果 | 数据来源 |
|---|---|---|
| 视图展开 | 展示本次引用的定义、引用别名及嵌套关系；点击字段高亮其底层来源；计划中的视图可展开、收起 | A 保存的定义，B 实际展开时记录的字段映射与初始计划 |
| 优化步骤 | 上一步、下一步查看改写前后完整计划；突出变化节点，展示具体条件、索引范围及原因 | B 在每次真实改写时保存的快照，连续步骤可以前后核对 |
| 执行数据流 | 沿真实的父子依赖显示记录流向；点击节点或逐步切换，查看输入输出行数、扫描量、连接比较次数及节点耗时 | C 本次执行产生的统计，包含表达式中引用的子查询计划 |

执行数据流是执行结束后的统计回放，不是暂停执行的调试器。相关子查询的同一节点可能被调用多次，统计是累计值。只生成计划而未执行时，界面明确显示没有执行数据；缺失统计不会被伪装成零行。节点耗时可能包含子节点耗时，不应直接相加。

## 三、实际增加的查询优化

以前外层条件停在视图投影之外；现在对只选择、重命名直接字段的简单投影，能够按字段映射移动条件。

示例中的真实过程：

1. 将 `passed_students.id = 5` 按视图输出映射到内部字段。
2. 继续穿过仅选择字段的内层投影，得到 `students.id = 5`。
3. 将它与原有 `students.score >= 60` 合并。
4. 使用编号索引定位编号为 5 的记录，并保留成绩筛选。

原有连接条件下推、索引扫描选择和哈希连接替换也接入了真实步骤记录。关闭优化时仍正常展开视图，但不会显示并未发生的优化步骤。

这些改写不是对任何 SQL 都可使用：不随意穿过分组、去重、行数限制或复杂计算；外连接遵守保留侧限制。若没有可用的安全规则，保留原计划并如实说明。当前仍是规则优化器，不宣称找到了全局成本最低的计划。

步骤快照最多展示前 32 步，若超过会显示实际总数和截断说明；实际优化与执行不因此停止。最终执行计划始终可在“执行计划”页查看。

## 四、接口和权限处理

沿用已有 `/api/query`，查询结果可附加可选的 `teaching` 对象：

| 字段 | 含义 |
|---|---|
| views | 本次引用的视图定义、别名、上层视图、字段映射和底层来源 |
| baseline | 视图展开后、优化之前的计划 |
| steps | 每次真实改写的规则、原因、相关节点及前后快照 |
| step_count / trace_truncated | 实际步骤数与展示是否截断 |
| optimizer_enabled | 本次是否开启优化 |
| execution_kind | 实际执行后的统计回放，或只生成计划 |

该字段是附加元信息，不改变 C 模块的算子执行语义。默认编译接口不采集完整教学快照；工作台按需开启。完整查询在完成权限检查后才返回；只获得视图权限但缺少基表读取权限的成员，不能获得展开信息。审计和报告不会额外存储含字面量的教学快照。

优化实验的计时运行关闭教学快照采集，避免把绘图数据准备开销混入两种计划的实验对比。查看过程和切换步骤不会再次执行查询。
