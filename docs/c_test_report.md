## 演示结果

命令：`python -m edudb.c_demo`。临时目录内插入 80 行，缓冲容量 2，直接提供基线和索引两个已绑定计划，不经过 B 的 SQL 解析或优化器。

| 指标 | 顺序扫描＋过滤 | 索引扫描 |
|---|---:|---:|
| 结果行数 | 1 | 1 |
| 数据页实际读取 | 10 | 1 |
| 索引页实际读取 | 0 | 5 |
| 扫描记录数 | 80 | 1 |
| 本次执行时间 | 4.884 ms | 4.205 ms |

两套计划结果一致；数据页与索引页合计分别读取 10 和 6 次。页枚举和缓存淘汰可能导致同一页重复读取，因此读次数不等于数据库文件中的唯一页数。缓存只重置本系统缓存，未清空操作系统文件缓存；时间仅是单次运行记录，不是严谨重复性能实验或固定收益承诺。

后续输出：

```text
Rollback restored table and index: OK
Reopen/recovery: redone=107, undone=0
```

redone 统计遍历并交给后端的重做记录，不等于实际重写页面数，后端依据 page_lsn 跳过已应用记录。

## 故障证据及边界

- 子进程调用 `os._exit`，无正常 close：已提交记录与索引保留，未提交记录及索引被撤销。
- 子进程在 CLR 已持久化、撤销页尚未应用时退出：重开可继续恢复，再次重开仍保持正确。
- 提交完整日志仍在而一个生成的临时数据页缺失时，可以根据完整页镜像 WAL 重建。
- 完整 WAL 帧校验损坏被拒绝，不伪装成成功恢复；不足一帧的尾部被截断。
- 测试模拟页面写入后异常、日志同步失败。提交同步失败不预设已回滚，标记需恢复后确认。

尚未验证：真实机器断电、介质损坏和 WAL 遗失、A 正式缓冲池适配、B SQL 编译器及视图展开、D 权限/Web、超大数据和长时间压力。现有测试证明 C 初版及参考适配可运行，不代表整个数据库项目已经完成。
