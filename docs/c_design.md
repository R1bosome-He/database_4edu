# C 模块实现方法

## 执行路径

`PlanNode -> QueryExecutor -> 算子生成器 -> RecordAccess/IndexManager -> PageStore`。
execute 先拿结构目录共享锁，再收集计划（含子查询）涉及的表，按稳定次序加锁。查询输出使用列位置列表，表达式通过 slot_id 绑定；自连接和同名列不会覆盖。

算子内部使用生成器，外部提供 open/next_batch/close。流式扫描、过滤和投影可逐行组合；排序、分组和连接右侧需要物化，显式计算保守内存预算，超限失败。最终结果也是受预算约束的物化结果。

外连接按左右是否匹配补 NULL；哈希连接忽略 NULL 键并继续验证完整 ON 条件。GROUP BY 的 NULL 归为一组。相关子查询把当前行压入外层作用域栈，退出及异常都弹出。视图应由 B 展开，因此无需在执行器中重复实现一种“视图查询算法”。

修改语句先收集目标旧行，之后按旧值同时计算赋值，避免修改索引后重复访问目标。每次表修改都维护同事务的索引。CHECK/唯一性/外键为立即约束；任一执行错误中止整个显式事务，而非只撤销最后一行。

## B+ 树

叶条目按 `(key,page_id,slot_id)` 排序：重复键可跨叶，同时保持条目唯一。内部节点记录子树最小键分隔符。叶子分裂后接入 next 链，内部溢出继续向上分裂。删除优先向相邻节点借条目或孩子，否则合并并向上修复；根只有一个孩子时收缩。

validate 检查占用率、排序、父子关系、等深叶、分隔键、叶链及可达性。持久化时节点各用独立索引页，页 0 为超级块；只写内容变化的页，对删除节点写墓碑。树根变化与索引目录一起写 WAL。查询沿根到叶的路径懒读节点，范围扫描沿叶链；为降低初版复杂度，修改仍从页加载全树并刷新分隔符，尚未实现局部修改路径。

## 事务和恢复

采用严格两阶段表锁；锁等待超过指定时间中止当前事务。单进程多会话支持线程等待；操作入口防止同一事务同时执行两条语句。独立进程锁禁止两个 Runtime 写同一数据目录。

写入顺序：获取锁 → 读前镜像 → 形成后镜像 → WAL UPDATE → fsync WAL → 持久化页（page_lsn=日志 LSN）。提交追加 COMMIT 并 fsync，随后释放锁。参考后端写穿，正式 A 缓冲池可在遵守 WAL 后采用脏页写回。

回滚逆着事务日志链撤销 UPDATE。每次撤销先写并持久化 CLR（包含撤销后的镜像和 undo_next_lsn），再修改页；恢复中断后可从 CLR 继续，避免重复撤销覆盖后续状态。页删除用带 LSN 的墓碑，而非丢掉历史标记。

启动从完整日志分析事务状态，按 LSN REDO UPDATE/CLR（页 LSN 已足够新则跳过），然后撤销没有 COMMIT/ABORT 的事务。已完成帧校验失败拒绝启动；不足一帧的尾部截断。保留全部日志使恢复简单且可重复，后续才实现检查点恢复起点和日志裁剪。

## A 基础代码与参考适配

保留仓库 a567eff 的原始 M1 文件和 21 个测试。原始固定页没有 page_lsn，记录页不能直接表示索引节点，因此新增 integration 层，不偷偷改变 A 的磁盘格式。

参考后端使用 4KB EDC1 页、长度及 CRC、页 LSN、任意结构化载荷及 tombstone；通过原始 atomic_write 落盘。CatalogBridge 使用同一 WAL 页管理表定义和约束，RecordAdapter 复用原始模型和多数 RecordStore 行为。它用于独立验证 C，正式合并时仍需 A 复核替换。

该恢复机制的测试覆盖进程异常退出及撤销中断；文件校验不等于防篡改，不承诺真实硬件断电、存储介质损坏或 WAL 文件遗失后的恢复。
