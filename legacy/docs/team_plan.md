# 分工与阶段计划

## 阶段 1：需求和架构设计

目标：确定 SQL 子集、模块边界、数据流、提交物。

产出：

- 系统架构图：SQL 输入 -> 查询处理器 -> 优化器 -> 执行引擎 -> 缓冲管理器 -> 存储管理器。
- SQL 范围：`CREATE TABLE`、`INSERT`、`SELECT`、`JOIN`、`WHERE`、`CREATE INDEX`、`EXPLAIN`、`COMPARE`。
- 安全范围：用户、密码、表级权限、审计日志。

## 阶段 2：存储管理器和缓冲管理器

负责人建议：成员 A。

任务：

- 设计表目录、页文件和记录格式。
- 实现页读写、表创建、记录插入。
- 实现 LRU 缓冲池、脏页写回、I/O 统计。

验收：

- 可以创建表、插入 1000 条以上数据。
- 可以统计磁盘读写、缓冲命中、页访问数。

## 阶段 3：SQL 解析和执行引擎

负责人建议：成员 B。

任务：

- 实现 SQL 子集解析。
- 实现逻辑计划和物理执行算子。
- 支持 `SeqScan`、`Filter`、`Projection`、`NestedLoopJoin`。

验收：

- 单表查询、条件查询、Join 查询结果正确。

## 阶段 4：索引和查询优化

负责人建议：成员 C。

任务：

- 实现 B+ 树索引创建、持久化和查询。
- 实现索引选择、谓词下推、Hash Join。
- 实现 `EXPLAIN OPTIMIZER ON/OFF`。
- 实现 `COMPARE SELECT ...` 优化对比。

验收：

- 同一 SQL 在优化关闭和开启时执行计划不同。
- 索引查询的磁盘读页数明显下降。

## 阶段 5：安全、界面和报告

负责人建议：成员 D。

任务：

- 实现用户登录、授权、权限校验。
- 实现审计日志。
- 整理 README、测试报告、答辩 PPT 和演示脚本。

验收：

- 未授权用户无法查询表。
- 所有成功/失败 SQL 都有审计记录。
- 可以一键运行 `python -m edu_dbms --demo` 完成演示。

## 3 人小组压缩版

- 成员 A：存储管理器、缓冲管理器、测试数据。
- 成员 B：SQL 解析、执行引擎、CLI。
- 成员 C：索引、优化器、安全、报告整合。
